## 今回の対応

<!-- 週次タスクが書き足す：自動で直したもの（PR）／要承認の提案（PR）／見送ったもの と理由 -->
初回の週次。開いている `seo-alert` の Issue、前回の「要承認」PR はなし。

- **A（自動で直したもの）**
  - `tools/seo/weekly.sh`：リポジトリに package-lock.json がないため、`node_modules` のない環境で `npm ci` が失敗してビルドできなかった。ロックファイルがないときは `npm install --no-package-lock` を使うように修正（点検ツール自体の不具合）。
  - 文書：スケジュールタスクの ID と方式を更新（`trig_01RrZBY7DC79EtMXno9werew`、専用セッションに毎週届く方式、通知はプッシュのみ）。
- **B（要承認の提案）**：なし。
- **C（見送り）**
  - title の長さ（注意 16 件）：サービスは「サービス名｜内容」、記事は記事の題名が先頭にあり、検索結果で切れるのは末尾の会社名だけ。文言はオーナーが決めたもので、短くする利益が小さいため今週は提案しない。
  - 表示速度（モバイル Performance 38〜55、LCP 9〜13 秒）：今回が基準値（初回）。主な要因の候補は、JS が 1 本で約 820KB（gzip 前）、Google Fonts（Noto Sans JP）の読み込み。コード分割はアニメーションや表示への影響の確認が大きいため、小さな週次 PR ではなく、来週も同水準なら原因の調査と案をまとめる。
  - セキュリティのヘッダー（HSTS なし）：SEO の点検の対象外。必要ならオーナーが Cloudflare の管理画面（SSL/TLS → Edge Certificates → HSTS）で設定できる。
  - 実際の利用者のデータ（PSI）：無料枠の上限（429）で取得できず。`PSI_API_KEY`（無料）の登録で安定する（オーナーにお願い、任意）。
