# コラム執筆ガイド（content/topics）

coana.co.jp のコラムは、読者が「読んでよかった」「この会社に相談したい」と思い、問い合わせにつながることを目的に書きます。`content/topics` の記事を新しく書くとき・直すときは、このガイドに従ってください。

---

## 1. 読者像

- **従業員0〜20名の中小企業の経営者・個人事業主**
- 経理・バックオフィス・集客を、本業のかたわら自分（または少人数）でこなしている
- 専門用語に詳しいとは限らない。「結局どうすればいいか」「いくら・どれくらいかかるか」「自分の会社の場合は？」を知りたい
- 忙しいので、スマホで流し読みすることが多い

書くときは「この読者が、読み終えたあとに自社で何をすればよいか分かるか」を常に確認します。

## 2. 記事の構成

次の順番を基本にします。見出しの名前は記事に合わせて変えてかまいません。

| 順番 | 要素 | 書き方 |
| --- | --- | --- |
| 1 | 導入（2〜3文） | 読者の悩みに共感し、**この記事で何が分かるか**を明示する |
| 2 | 結論の先出し | 答えを最初に短く言い切る（太字1〜2か所まで） |
| 3 | 本文 | 見出しごとに1テーマ。理由→具体例→やること の順 |
| 4 | チェックリスト | 読者が自社でそのまま使える確認項目（5〜8項目） |
| 5 | よくある失敗 | 「〜しがち」→「こうすると防げる」をセットで2〜4個 |
| 6 | まとめ | 3〜5文。本文の要点の繰り返しでよい |
| 7 | CTA | 関連サービスページと /contact への誘導（→ 6. CTA） |

その他のルール：

- 1段落は2〜4文まで。スマホで縦に長い塊を作らない
- 箇条書きは「何を・どうする」が分かる短い文に
- 記事末尾の著者欄（`執筆：…`）は既存の書式のまま残す
- 既存記事を直すときは、`date`・`slug`・ファイル名・`draft`・`thumbnail`・著者欄は変えない

## 3. 図解のルール

- **1記事あたり2〜4点**
- **関連する見出しの直後**に置く（本文を読む前に全体像がつかめるように）
- 本文の理解を助けるものに限る。例：
  - 比較表（A案とB案、任せる／任せない）
  - フロー図（手順、資料の流れ）
  - チェックリスト
  - Before / After
  - 費用や時間の構造図（何がいくらを左右するか）
- **装飾だけの画像（イメージ写真・アイコンの並びなど）は不可**
- 図解の中身は本文と矛盾させない。図にしか書いていない重要情報も作らない（画像が読めない人にも本文で伝わるように）

## 4. 図解の作り方

### ファイル

- 保存先：`public/images/topics/<slug>/`（`<slug>` は front matter の `slug`）
- 形式：SVG。ファイル名は内容が分かる英語のケバブケース（例：`cost-factors.svg`）

### サイズ・文字

- `viewBox` の幅は **600**（高さは内容に合わせる）。`width` / `height` 属性は付けず、`viewBox` だけにする
- 記事ページでは、図解は **PCで最大640px幅・中央寄せ**、スマホでは本文幅いっぱい（375px幅の端末で約335px）に表示される
- 文字サイズは、スマホ（375px幅）で**実寸14px以上**になるようにする
  - 本文・項目の文字：**26px**（最低でも24px。26pxなら375px幅で約14.4px）
  - 図のタイトル・見出し：**28〜30px**（28px以上）
- 文言は短く。**1行あたり全角8〜12文字程度**を目安に、はみ出しそうなら言葉を削る（26pxで12文字＝約312px）
  - 2列のカードなら1行8〜9文字、3列なら1行5文字程度まで
  - 枠の内側に左右12px以上の余白を残す
- フォント：`font-family="'Noto Sans JP','Hiragino Kaku Gothic ProN',sans-serif"`
  - SVG を `<img>` で表示するとサイトの Web フォントは使われず、端末のフォントで描画される。幅に余裕を持たせる

### 配色

`src/index.css` の `:root` にある色だけを使います。

| 用途 | 色 |
| --- | --- |
| 文字・濃い線・強調の帯 | navy `#16334d`（補助文字は navy-soft `#4a667d`） |
| アクセント・矢印・強調枠 | sky-deep `#087fe5` |
| 補助のアクセント | sky `#55b8f3` |
| 目立たせたい1か所 | yellow `#ffd85a`（薄い背景は yellow-soft `#fff7df`） |
| 罫線・枠 | line `#d8e7f2` |
| 背景 | `#ffffff` / paper `#fbfdff` / ivory `#eef6fc` |

- 黄色は1つの図で1か所程度に絞る
- 白背景に sky `#55b8f3` の文字は薄くて読みにくいので、文字には使わない

### 記事への挿入

Markdown の画像記法ではなく、次の HTML をそのまま書きます（キャプションを付けるため）。前後には空行を入れます。

```html
<figure class="article-figure">
  <img src="/images/topics/<slug>/<file>.svg" alt="（図の内容を文章で説明した代替テキスト）" width="600" height="（viewBoxの高さ）" loading="lazy">
  <figcaption>図1：（図のタイトル）</figcaption>
</figure>
```

- `alt`：画像が見えない人にも内容が伝わるよう、図の要点を1〜2文で書く（「図」「画像」だけは不可）
- `figcaption`：「図1：」から始まる短いタイトル
- `width` / `height` には viewBox の幅・高さを入れる（表示時のレイアウトのずれを防ぐ）

### 確認

作った SVG は、ブラウザやヘッドレス Chrome で PNG に描画し、**文字のはみ出し・重なり・欠け**がないか目視で確認します。PC幅（1280px）とスマホ幅（375px）の両方で記事ページの見え方も確認します。

公開日が未来の記事は、Cloudflare Pages のプレビュー（`*.pages.dev`）とローカル（`localhost`）に限り、URLに `?preview=YYYY-MM-DD` を付けるとその日付時点の表示で確認できます（例：`/topics/20261110-bookkeeping-outsourcing-cost?preview=2026-11-10`）。本番（coana.co.jp）では使えません。

## 5. 信頼性

- 税務・法令・料金などの数字は、**一般に確認できる事実のみ**書く（国税庁・法令・公的機関の情報など）。必要なら出典を添える
- 不確かな数値、架空の統計・調査結果は書かない。「相場は月○万円」のような裏付けのない金額も書かない
- **実在しない顧客の事例・お客様の声は作らない**。例示は「例えば、従業員5名の小売店の場合」のように、仮の例と分かる書き方にする
- 税務の判断は税理士の業務。税務申告・税務相談に触れるときは「具体的な判断は顧問の税理士にご確認ください」などの一文を添える
- 自社のサービス内容は、サイト内（`content/solutions/*.json`、`content/services.json` など）の記述と食い違わないようにする

## 6. CTA

- **記事末尾**に次の3つを入れる
  1. 関連するサービスページ（`/services/<slug>`）への具体的な誘導（このページで何が分かるか）
  2. お問い合わせ（`/contact`）への誘導
  3. 敷居を下げる一文（例：「何から任せればよいか分からない段階でもご相談ください」）
- 末尾の CTA の節では、**いちばんつなぎたいサービスLPを最初に**書く。記事の末尾の「この記事に関連するサービス」の案内と、記事からのお問い合わせで選んでおく「ご相談内容の種別」は、この最初のLPになる。別のLPにしたいときは front matter に `service: <slug>`（CMS の「つなぐサービス」）、出したくないときは `service: none`
- 無料相談・対応エリアなどの条件は、サイト内の既存の記述に合わせる（現状：「ご相談・お見積もりは無料」「全国オンライン対応」）。**サイトにない約束（○日以内に返信、初月無料など）は書かない**
- **記事の途中にも1回**、文脈に合う自然な関連リンク（サービスページまたは関連コラム）を入れる。押し売りの言い回しは避ける

## 7. SEO

- `title`：検索する人が使う具体的な言葉を入れる（例：「経理代行 費用」「小さな会社」）。32〜40文字程度を目安
- `summary`：検索結果やカードに出る説明。誰向けに・何が分かるかを、80〜120文字程度で具体的に
- 見出し（`##`）に検索語を自然に含める（詰め込みすぎない）
- **関連コラムへの内部リンクを1〜2本**入れる。リンク先は、その記事の公開日時点ですでに公開されている記事を選ぶ（予約投稿の記事は公開日まで表示されないため）
- リンクは `/topics/<ファイル名から .md を除いたもの>` の形式
