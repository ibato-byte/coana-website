# モーションのルール

## いちばん大事なこと

1. **見やすさ・分かりやすさが最優先。** 初めて訪れた中小企業の経営者が「何をしてくれる会社か」「自分に合うサービスはどれか」「どう相談すればいいか」を、迷わずすぐ分かること。
   - 文字・数字・ボタン（＝情報）は、画面に入ったらすぐ読める状態に。演出で文字を隠したり、読み始めるまで待たせたりしない。
   - 文字と背景のコントラストは WCAG AA（通常の文字 4.5:1、大きな文字 3:1）を満たす。
   - 演出をすべて止めても（「動きを減らす」設定）、分かりやすさは同じであること。
2. **そのうえで、楽しさと技術力をしっかり見せる。** 「全部地味にする」のではない。
   - 線・アイコン・イラスト・ボタン・鳩・ホバー反応などの**装飾やインタラクション**で、「触ると楽しい」「よく見ると細部まで作り込まれている」という発見をつくる。
   - 引き算するのは「情報を邪魔している演出」だけ。そうでない演出は、精度を上げて磨き込む。

サイト全体（トップのヒーロー・OUR STYLE、サービス一覧と各LPの PROBLEMS・HOW IT WORKS・FLOW、ボタン）で共通の決まりごと。
新しく動きを足すときも、この表の値と考え方に合わせる。仕組みは `src/motion.ts`、値は `src/index.css` の `--m-*`。

## 共通のモチーフ：「線でつなぐ／線で描く」

- 動きの主役は**1本の線**。ステップ・カード・図の要素を線がつないでいき、アイコンは線で描かれる。
- **黄色（--yellow）**は「ここが要点・いま触れているところ」の合図（見出しの下線、ホバーしたステップ、線が届いた点、ボタン）にだけ使う。
- 光り物・跳ねる動き・回転・拡大縮小の強調は使わない。ボタンの「矢印 → 鳥」と同じく、形と線で見せる。

## 値

| 項目 | 値 | 変数 |
| --- | --- | --- |
| イージング（現れる・移る） | `cubic-bezier(.22, 1, .36, 1)`（速く始まり、静かに止まる） | `--m-ease` |
| イージング（線を引く） | `cubic-bezier(.65, 0, .35, 1)`（両端がなめらか） | `--m-ease-line` |
| 文字・カードが現れる時間 | 0.32 秒（移動は 8px まで。画面に入る少し前に始める） | `--m-text` |
| 順に現れるときの間隔 | 0.06 秒（4枚でも最後が 0.6 秒以内に読める） | `--m-stagger` |
| 線・アイコンを描く時間 | 0.8 秒（アイコンは 0.6 秒） | `--m-draw` / `--m-icon` |
| 色が変わる時間 | 0.3 秒 | `--m-color` |
| 繰り返す動きの周期 | 6 秒以上（光の粒・光のグラデーション） | — |
| 線の太さ | つなぐ線 2px（図の中は 2.5px 相当、FLOW は 1px の細い線）、アイコンの線 1.6〜2px | `--m-line` |
| 線の色 | ふだん：薄い水色（--line、FLOW は青 26%）、強調：--sky-deep、届いた点・ホバー：--yellow | — |

## 見せ場は1ページに2〜3か所まで

| ページ | 強い見せ場 | 控えめ |
| --- | --- | --- |
| トップ | ヒーロー（PC はピン留め＋スクロールで言葉とカードが切り替わる、スマホ・タブレットは約7秒ごとの自動切り替え。入りは言葉が下から順に・カードが右から）＝Signal Sky、2026-10-23 | 空の白い羽（canvas、画面内だけ舞い上がる）・ヒーロー下の帯（画面内だけ流れる、PC のみ）・サービスの行のカーソルについてくる「詳しく見る」（PC のみ） |
| サービス一覧 | FLOW（相談の手紙が進むアニメーション＋PC のホバー） | ほかは見出しが現れるだけ |
| 各サービスLP | ヒーロー、HOW IT WORKS（仕組みのアニメーション） | FLOW（小さな手紙が丸の上を進むだけ＋PC のホバー）、PROBLEMS（順に現れて線が集まるだけ） |

- 同時に複数の場所を動かさない（1画面に入る範囲で、動いているのは1つのまとまりだけ）。
- 繰り返す動きは、画面に入っている間だけ・ごく穏やかに（`[data-live]` / `.is-live`）。スマホでは繰り返す動きを止める。

## スクロールとの関係（必ず守る）

- 例外（2026-10-23 オーナー決定）：トップのヒーローは PC（幅1101px以上・高さ700px以上）でピン留めし、1.8画面分のスクロールで 整える→任せる→伸ばす を切り替える（選ばれていない言葉は輪郭）。それ以外の画面は約7秒ごとの自動切り替え。reduced-motion では固定も自動切り替えもしない。

- スクロールを乗っ取らない：スクロールジャック、速度の変更、画面の固定（pin）、スクロールスナップは使わない。
- 演出のためにセクションの高さを伸ばさない（ページの長さは変更前以下）。線や光は既存の余白・背景に描く。
- 文字・数字・ボタンは、画面に入ったときにはほぼ読める状態に（画面の下端より少し手前で表示を始め、0.3 秒ほどで完了）。
- スクロールの量に連動して線が伸びる・番号が変わる、といった動きは使わない（見づらいため。FLOW は最初から完成した状態で見せ、PC のホバーで反応する）。
- 画面より上にあるもの（一気に下まで・ページ内リンク・戻るボタン）は、動きなしで表示済みにする。
- 一度表示したものは、上に戻っても消さない・やり直さない。線も戻らない。
- 演出は「ページに入るたびに同じ」にする。初回読み込みだけ動く・2回目以降は省略、という作りにしない（入り方を変えて同じ演出になるか、最終チェックで確かめる）。
- レイアウトは動かさない（transform と opacity、SVG の線の描画だけ）。CLS を悪化させない。

## HOW IT WORKS・FLOW：鳩がデータを運ぶ（src/doveCarrier.tsx が共通、LPごとの順路は src/schemeStory.tsx・src/flowJourney.ts）

- 小さな鳩（白い体・丸い目・黄色のくちばし。絵本のようなシンプルなシルエット。しゃべらない・ふざけない）が、くちばしに荷物のカード（領収書・会計データ・レポート・手紙など）をさげて、工程から工程へ1つずつ届ける。一度に動くのは1羽。
- LPごとに変えるのは「運ぶもの」と「順路」だけ。動き・タイミングはすべて共通。各LPで「このアニメーションで伝えたい一文」（STORIES の message）を先に決め、それが説明なしで伝わるかで判断する。
- **起点が1秒以内に分かること**（合格条件）：
  - 初期表示から、起点の工程で鳩が荷物を持って待っている（画面に入る前から。動き出す前でも起点が見える）。点灯しているのは起点の工程だけ。
  - **起点は追加の印（点・バッジ・マーク・文字ラベル）で示さない。鳩とカードの状態だけで示す**：
    - 起点のカードは、到着したときと同じトーンで控えめに点灯（御社のカードは暖色の縁、COANA TOKYO 側は青の縁）。
    - 鳩は待っている間に一度だけ、首をかしげて荷物を持ち直す小さな仕草（約0.7秒）。視線を鳩＝起点へ自然に導く。くり返さない。
    - 出発の直前に、次の工程の方へ向き直る（起点から ① の矢印へのつながりが読める）。
  - 起点の工程が画面に入ってから（約85%以上）出発する。スマホで図の下のほうだけ見えているときは出発しない。
- **軌道は描かない**：鳩の飛ぶ道筋・軌跡・点線の先出しは出さない。進み具合はカードの側で見せる（いま届いたカードが点灯、届け終えたカードに小さなチェック `StepCheck`）。図の意味のある矢印・接続線（工程の順番を示すもの）は残してよく、通り終えた区間だけ色が濃くなる。
- 飛び方：工程から工程へ、短く自然な弧だけ（横向きの移動は上へふくらみ、縦の移動は横へふくらむ。文字に当たらない高さ・向きを自動で選ぶ）。大きな迂回やカードの裏をくぐる動きはしない。文字を避けるのは止まる位置（perch）で決める。
- 時間：起点で約1.4秒待つ（静止 → 小さな仕草 → 静止 → 進む方を向く）→ しゃがむ（予備動作）→ 約1秒で弧を描いて次の工程へ → 着地でわずかにつぶれ、荷物は少し遅れて揺れが収まる → 荷物をそっと置く → 少し止まる → …
- **終点から起点へ飛んで戻らない**。終点では：荷物をそっと置く → 全工程が「完了」で一瞬そろう（約1.2秒）→ 鳩は上へふわっと去る（約0.7秒・フェード）→ 点灯が静かに消える（くり返す図は「毎月くり返し」の印が小さく回る）→ 起点のカードが点灯し、鳩が新しい荷物を持って舞い降りる（約0.85秒）→ 静止（約0.9秒）→ 出発。去ってから舞い降りるまでの「何もない時間」は約0.35秒（「止まった？」と思わせない）。ワープはしない。
- 文字に重ねない：止まる位置はカードの右上の空き（data-perch="in-tr"）、上の縁（above-tr・above-c）、カードの右の外の余白（out-r）、グループの右上（group-tr）。
- スマホ（カードが縦に積まれる）：カードの右に鳩の通り道の余白（padding-right）をとり、鳩はそこに止まって、右の余白を縦に短い弧で進む。FLOW は丸の列の右上に止まる（parent-tr）。
- 軽さ：動かすのは transform と opacity だけ（Web Animations API と CSS animation。rAF で毎フレーム DOM を書き換える処理はない）。位置と文字の計測は飛ぶ前に1回だけ。動く部品は最初から合成レイヤー。工程の強調（枠の輪）は重ねた輪の opacity だけで出し入れする（box-shadow は動かさない）。
- 止める：画面外・タブが非表示・カードを読んでいる間（readingPause.ts。カード上でカーソルを動かしている／フォーカス中。約2.5秒で再開）・工程の説明を開いている間。セクションに入っただけでは止めない。
- 「動きを減らす」設定では鳩を出さず、全工程を終えた状態で見せる。
- 確認：tools/qa/dove-overlap.cjs（文字との重なり。止まっている間も飛んでいる間も）、story-test.cjs・fj-test.cjs・wheel.cjs・fj-wheel.cjs（進む・止まる・繰り返す）、dove-perf.cjs（CPU 1x/4x/6x）。

## 端末と設定

- PC（マウス）だけ：カードのわずかな傾き（最大 3°）と光の追従、図のホバーで関係する線だけ強調、FLOW のホバー（ステップが浮いて丸が黄色に、アイコンを描き直し、前後の線が濃くなる）。
- スマホ：移動量を小さく、光の粒・光のグラデーションの動き・傾きはなし。
- 「動きを減らす」（prefers-reduced-motion）：すべて静止し、最初から全部表示（線も引き終えた状態）。
