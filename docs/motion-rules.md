# モーションのルール

## いちばん大事なこと

1. **見やすさ・分かりやすさが最優先。** 初めて訪れた中小企業の経営者が「何をしてくれる会社か」「自分に合うサービスはどれか」「どう相談すればいいか」を、迷わずすぐ分かること。
   - 文字・数字・ボタン（＝情報）は、画面に入ったらすぐ読める状態に。演出で文字を隠したり、読み始めるまで待たせたりしない。
   - 文字と背景のコントラストは WCAG AA（通常の文字 4.5:1、大きな文字 3:1）を満たす。
   - 演出をすべて止めても（「動きを減らす」設定）、分かりやすさは同じであること。
2. **そのうえで、楽しさと技術力をしっかり見せる。** 「全部地味にする」のではない。
   - 線・アイコン・イラスト・ボタン・鳩・ホバー反応などの**装飾やインタラクション**で、「触ると楽しい」「よく見ると細部まで作り込まれている」という発見をつくる。
   - 引き算するのは「情報を邪魔している演出」だけ。そうでない演出は、精度を上げて磨き込む。

サイト全体（トップのヒーロー・OUR STYLE、サービス一覧と各LPの PROBLEMS・HOW IT WORKS・FLOW、ボタン）で共通の決まりごと。
新しく動きを足すときも、この表の値と考え方に合わせる。仕組みは `src/motion.ts`、値は `src/index.css` の `--m-*`。

## 共通のモチーフ：「線でつなぐ／線で描く」

- 動きの主役は**1本の線**。ステップ・カード・図の要素を線がつないでいき、アイコンは線で描かれる。
- **黄色（--yellow）**は「ここが要点・いま触れているところ」の合図（見出しの下線、ホバーしたステップ、線が届いた点、ボタン）にだけ使う。
- 光り物・跳ねる動き・回転・拡大縮小の強調は使わない。ボタンの「矢印 → 鳥」と同じく、形と線で見せる。

## 値

| 項目 | 値 | 変数 |
| --- | --- | --- |
| イージング（現れる・移る） | `cubic-bezier(.22, 1, .36, 1)`（速く始まり、静かに止まる） | `--m-ease` |
| イージング（線を引く） | `cubic-bezier(.65, 0, .35, 1)`（両端がなめらか） | `--m-ease-line` |
| 文字・カードが現れる時間 | 0.32 秒（移動は 8px まで。画面に入る少し前に始める） | `--m-text` |
| 順に現れるときの間隔 | 0.06 秒（4枚でも最後が 0.6 秒以内に読める） | `--m-stagger` |
| 線・アイコンを描く時間 | 0.8 秒（アイコンは 0.6 秒） | `--m-draw` / `--m-icon` |
| 色が変わる時間 | 0.3 秒 | `--m-color` |
| 繰り返す動きの周期 | 6 秒以上（光の粒・光のグラデーション） | — |
| 線の太さ | つなぐ線 2px（図の中は 2.5px 相当、FLOW は 1px の細い線）、アイコンの線 1.6〜2px | `--m-line` |
| 線の色 | ふだん：薄い水色（--line、FLOW は青 26%）、強調：--sky-deep、届いた点・ホバー：--yellow | — |

## 見せ場は1ページに2〜3か所まで

| ページ | 強い見せ場 | 控えめ |
| --- | --- | --- |
| トップ | ヒーロー（下線を鳩が引いて飛び去る。ヒーローが表示されるたびに1回。再読み込み・ロゴ・メニュー・戻る/進む・他ページからの移動のどれでも同じ）、OUR STYLE | ほかは見出しが現れるだけ |
| サービス一覧 | FLOW（相談の手紙が進むアニメーション＋PC のホバー） | ほかは見出しが現れるだけ |
| 各サービスLP | ヒーロー、HOW IT WORKS（仕組みのアニメーション） | FLOW（小さな手紙が丸の上を進むだけ＋PC のホバー）、PROBLEMS（順に現れて線が集まるだけ） |

- 同時に複数の場所を動かさない（1画面に入る範囲で、動いているのは1つのまとまりだけ）。
- 繰り返す動きは、画面に入っている間だけ・ごく穏やかに（`[data-live]` / `.is-live`）。スマホでは繰り返す動きを止める。

## スクロールとの関係（必ず守る）

- スクロールを乗っ取らない：スクロールジャック、速度の変更、画面の固定（pin）、スクロールスナップは使わない。
- 演出のためにセクションの高さを伸ばさない（ページの長さは変更前以下）。線や光は既存の余白・背景に描く。
- 文字・数字・ボタンは、画面に入ったときにはほぼ読める状態に（画面の下端より少し手前で表示を始め、0.3 秒ほどで完了）。
- スクロールの量に連動して線が伸びる・番号が変わる、といった動きは使わない（見づらいため。FLOW は最初から完成した状態で見せ、PC のホバーで反応する）。
- 画面より上にあるもの（一気に下まで・ページ内リンク・戻るボタン）は、動きなしで表示済みにする。
- 一度表示したものは、上に戻っても消さない・やり直さない。線も戻らない。
- 演出は「ページに入るたびに同じ」にする。初回読み込みだけ動く・2回目以降は省略、という作りにしない（入り方を変えて同じ演出になるか、最終チェックで確かめる）。
- レイアウトは動かさない（transform と opacity、SVG の線の描画だけ）。CLS を悪化させない。

## HOW IT WORKS：仕組みのアニメーション（src/schemeStory.tsx）

- 各LPで「このアニメーションで伝えたい一文」を先に決め、それが説明なしで伝わるかで判断する（一文は STORIES の message）。
- 図の工程のあいだを、ラベル付きの小さなチップ（「領収書」「会計データ」「見込み客」など）が1つずつ移動する。一度に動くのは1つ。
- 1回の移動は約0.9秒（なめらかな加減速）。着いたらカードの上の縁に止まり（文字に重ならない）、その工程をそっと強調して約0.75秒止まる。一周は約8〜15秒。
- 一周したら、完成した状態のまま約8秒ひと息置いて繰り返す。画面外・タブが非表示・図にカーソルを当てている・工程の説明を開いている間は止める。
- 「動きを減らす」設定では動かさず、全工程を終えた状態で見せる。

## FLOW：お客さまの「相談」が進んでいくアニメーション（src/flowJourney.tsx）

- 小さな手紙（＝相談）が、ステップの丸の上の余白を弧を描いて進む。文字・番号には重ならない（スマホは丸の列の中だけを進み、次の丸へは丸の後ろをくぐる）。
- 各ステップで小さな出来事：届く（波紋）／ヒアリング（吹き出しが交わる）／提案（封が開いて提案書）／準備（チェック）／契約（印）／スタート（提案書が矢印に折られ、ボタンと同じ鳥になって飛び立つ）／改善・伴走（舞い降りて「続いていく」輪）。
- アニメーションの原則：予備動作（跳ぶ前に少し沈む）、スローイン・スローアウト、弧の動き、控えめなスクワッシュ＆ストレッチ、フォロースルー（着地で少しつぶれて伸び返す）、影は高さに応じて小さく。キャラクター（目や顔）は使わない。
- 1ステップ 約1秒の移動＋出来事の間。一周したら約9〜11秒おいて繰り返す。画面外・タブが非表示・ステップにカーソルを当てている間は止める。「動きを減らす」設定では何も出さない。

## 端末と設定

- PC（マウス）だけ：カードのわずかな傾き（最大 3°）と光の追従、図のホバーで関係する線だけ強調、FLOW のホバー（ステップが浮いて丸が黄色に、アイコンを描き直し、前後の線が濃くなる）。
- スマホ：移動量を小さく、光の粒・光のグラデーションの動き・傾きはなし。
- 「動きを減らす」（prefers-reduced-motion）：すべて静止し、最初から全部表示（線も引き終えた状態）。
